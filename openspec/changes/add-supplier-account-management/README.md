# 供应商账号管理与系统令牌二开需求

状态：已实施；2026-09-23 增补供应商账号配置、代理与审核策略

日期：2026-09-22
变更标识：`add-supplier-account-management`

## 1. 背景

平台从多家号池供应商获取大量不同平台、不同账号类型的上游凭据。当前系统只有 `admin` 与 `user` 两种角色，所有上游账号都属于平台全局资源，新增、编辑、批量导入和删除账号的能力全部位于管理员接口中。

现阶段供应商只能把 Key 交给平台人员，再由平台人员导入。随着供应商和 Key 数量增长，这种方式存在以下问题：

- 导入依赖人工中转，效率低且容易重复或遗漏。
- 供应商无法自行查看自己提交账号的状态和失败原因。
- 无法通过稳定 API 与供应商系统自动同步。
- 如果直接把管理员 API Key 发给供应商，会赋予用户、余额、系统设置等完整管理员权限，风险不可接受。
- 当前账号没有供应商归属，无法从数据库层保证不同供应商之间的数据隔离。

## 2. 建设目标

新增独立的供应商租户能力，使每家供应商能够：

1. 使用供应商人员账号登录独立控制台。
2. 手工提交、批量提交和维护自己提供的上游账号凭据。
3. 生成一个长期供应商系统令牌，通过 API 完成同样的账号操作。
4. 只查看和操作归属于自己的供应账号。
5. 查看账号的审核状态、运行状态和经过脱敏的失败原因。

平台管理员能够：

1. 创建、编辑、启用和禁用供应商。
2. 为供应商创建或绑定登录成员。
3. 配置供应商允许提交的平台和账号类型。
4. 查看供应商账号并批量审核、拒绝、分组和启用。
5. 撤销供应商系统令牌并审计供应商操作。

## 3. 核心原则

- **供应商是租户，不只是角色**：`supplier` 表示登录身份，`supplier_id` 才是数据归属边界。
- **后端强制隔离**：所有供应商账号查询和写入必须同时携带认证上下文中的 `supplier_id`；不得依赖前端隐藏按钮。
- **最小权限**：供应商不能访问 `/api/v1/admin/*`；可选择平台库存中的有效代理并编辑账号并发、优先级、负载因子和过期停调，不能配置代理地址/凭据、分组、倍率、审核状态及系统级字段。
- **两种认证、一套权限**：网页登录使用 JWT，系统集成使用供应商令牌，最终都进入同一个供应商作用域服务。
- **默认不进入调度**：新账号默认待审核、停用且不可调度；仅管理员关闭该供应商审核要求并预设对应平台分组时，合法提交才自动审核并启用。
- **代理必选**：供应商创建、更新和管理员审核通过时，账号必须绑定有效且未过期的平台库存代理；库存为空时拒绝提交。
- **凭据不回显**：创建后不再返回完整上游 Key，列表、详情、日志和审计均只显示掩码或是否存在。
- **接口可安全重试**：创建和批量创建支持 `Idempotency-Key`，供应商外部编号在租户内唯一。
- **兼容现有数据**：历史账号保持管理员所有，升级后行为不变。

## 4. 完整交付范围

### 4.1 包含

- 供应商租户及状态管理。
- 供应商成员登录与 `supplier` 角色。
- 账号供应商归属和审核状态。
- 单供应商单个有效系统令牌的生成、重新生成和撤销。
- 供应商账号单个创建、批量创建、列表、详情、有限字段更新、暂停、软删除和测试。
- 管理员供应商列表、详情、成员管理、令牌管理和账号批量审核。
- 覆盖系统现有可独立供应的 `apikey`、`upstream`、`setup-token`、`oauth` 凭据包、`bedrock` 和 `service_account` 类型；每个实际 `platform + type` 组合都必须有独立严格校验。
- JSON、CSV 和逐行文本批量导入；系统 API 使用 JSON 作为稳定契约。
- 供应商自己的账号数量、待审核、可调度、异常和即将过期基础统计。
- 审计、限流、幂等、跨租户越权测试和 API 文档。

### 4.2 明确不包含

- 供应商结算、分成、账单和财务报表。
- 供应商内部的多级 RBAC；同一供应商成员权限相同。
- 一个供应商同时保留多个系统令牌。
- 供应商直接控制账号分组、代理地址/凭据、计费倍率或审核状态。
- Composite 和影子账号；它们是平台内部调度结构，不是供应商可独立供应的凭据。
- 供应商调用管理员专属授权接口，或为未获准的平台/类型发起换票；供应商仅能通过自己的授权入口和库存代理换取 Token。账号提交仍需提供网页登录核验的邮箱和密码（加密保存，仅管理员按需读取）。
- 供应商自行开启免审；该策略只能由平台管理员配置。
- 对现有全部 `accounts.credentials` 做应用层加密迁移；该工作另行立项。

## 5. 主要业务流程

### 5.1 供应商开通

1. 管理员创建供应商并配置允许的 `platform + account_type` 组合。
2. 管理员创建或绑定至少一个供应商成员。
3. 供应商成员使用现有登录入口登录，系统按角色跳转到供应商控制台。
4. 供应商成员可以在控制台生成系统令牌；完整令牌只显示一次。

### 5.2 账号提交

1. 供应商通过网页或 API 提交账号。
2. 服务端从认证上下文取得 `supplier_id`，忽略并拒绝请求中的任何归属字段。
3. 服务端检查该供应商是否允许提交对应的平台和账号类型。
4. 服务端按平台和类型验证凭据字段、长度和 Base URL。
5. 必须选择平台库存代理；默认保存为 `pending + inactive + schedulable=false`。免审供应商还须由管理员预设对应平台启用分组，创建时原子绑定并保存为 `approved + active + schedulable=true`。
6. 响应只返回账号 ID、外部编号、审核状态和非敏感元数据。

### 5.3 审核上线

1. 管理员在供应商详情中筛选待审核账号。
2. 管理员批量选择账号，配置分组及必要调度字段。
3. 审核通过后写入 `review_status=approved`，再启用账号和调度。
4. 驳回时写入 `review_status=rejected` 和管理员审核备注。
5. 默认供应商修改凭据或代理后，账号自动重新进入待审核并停止调度；免审供应商的已审核账号保持原审核/运行状态。
6. 仅修改名称或备注不改变审核状态。

### 5.4 系统同步

1. 供应商程序使用 `x-api-key: supplier_...` 调用供应商 API。
2. 单个和批量创建请求携带稳定的 `Idempotency-Key`。
3. 供应商已有自有系统编号时可通过可选的 `external_id` 传入，在当前供应商内唯一；不填时平台仍自动生成账号 `id`。
4. 重试相同请求返回原结果；同一幂等键配不同正文返回 409 `IDEMPOTENCY_KEY_CONFLICT`。

## 6. 完成定义

本功能只有在以下条件全部满足时才算完成：

- 两家不同供应商可同时存在并分别登录。
- 网页和系统令牌两条链路使用同一后端租户权限边界。
- 任意跨供应商读取、更新、测试和删除均返回 404，且不泄露资源存在性。
- 供应商无法访问管理员和普通用户业务接口。
- 新提交账号在审核前不会被调度。
- 供应商无法设置管理员专属字段。
- 完整系统令牌和上游凭据不会出现在数据库令牌字段、响应回显、普通日志或审计正文中。
- 批量导入可重试且不会重复创建账号。
- 现有管理员、普通用户、历史账号和网关调用行为无回归。
- 后端单元/集成测试、前端测试、类型检查、构建和 Docker 端到端验收全部通过。

## 8. 完整实现基线

按以下默认值实施；如业务确认不同，应先更新本变更文档再编码：

| 事项 | 实现基线 |
|---|---|
| 每家供应商成员数量 | 支持多个 |
| 每家供应商系统令牌数量 | 一个有效令牌 |
| 新账号是否自动进入调度 | 默认否；管理员配置免审和对应平台分组后可自动启用 |
| 供应商修改凭据后是否重新审核 | 默认是；免审供应商无需重新审核 |
| 供应商代理 | 必须选择平台库存有效代理；库存为空则拒绝提交 |
| 供应商能否软删除自己的账号 | 能 |
| 单批最大数量 | 500 条 |
| 单请求最大正文 | 2 MiB |
| 账号类型 | 所有现有可独立供应类型，排除 Composite/影子账号；已获准的 OAuth 类型可走供应商授权入口 |
| 批量导入格式 | API JSON；网页支持 JSON、CSV、逐行文本 |
| 供应商是否查看统计 | 提供账号状态基础统计，不提供财务结算 |
